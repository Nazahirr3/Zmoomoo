# MooMoo.io Clone

Fully working MooMoo.io private server

## Project structure
- `client/` Webpack-powered front-end source and static assets.
- `server/` Game server source (ES modules) and dependencies.
- `dist/` Build artifacts generated by the client build (ignored by git).

## Getting started
1. Install workspace dependencies:
   ```bash
   npm install
   ```
2. Build the web client into `dist/client`:
   ```bash
   npm run build
   ```
3. Start the game server (serves the bundled client and WebSocket API):
   ```bash
   npm run start
   ```

Use `npm run build:dev` while iterating on the client for an auto-rebuilt bundle, or `npm run dev` to run the server in development mode.

## Accounts

The server requires Node.js 22.13 or newer for its built-in SQLite storage. Copy `.env.example` to `.env`, create a Discord application, and add this callback URL in its OAuth settings:

```text
http://localhost:3000/api/auth/discord/callback
```

Set `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, and `DISCORD_REDIRECT_URI` in `.env`. Generate a private signing key for `JOIN_SECRET` with:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Keep `.env` private. On production, use HTTPS and set `DISCORD_REDIRECT_URI` to the matching HTTPS callback. Set `TRUST_PROXY=true` only when the server is behind a trusted reverse proxy.

The first successful Discord sign-in creates an account. Guests can still play without signing in. The OAuth flow validates state and uses PKCE (S256), requests Discord identity and verified-email data, and stores only a hashed session token. Sessions roll forward during use and can be invalidated by moderation or logout. Discord identities are stored in a separate provider-identity table linked to the game account. Google OAuth and user-facing provider-linking are not enabled. Accounts track kills, deaths, K/D, damage, healing, gathered resources, animal and boss kills, best score and kills, lives, and play time. Stats are saved when a player dies or disconnects. Account data is stored in `server/data/accounts.sqlite` by default; `ACCOUNT_DB_PATH` can change its location. Back up this database. The account panel includes stored-data details and account deletion.

The optional Discord bot uses the same Discord application but a separate bot token. Create or reset the token on the application's Bot page, add it as `DISCORD_BOT_TOKEN` in `.env`, and restart the server. It registers `/ping`, `/send`, `/sendglobalmessage`, `/restart`, `/update`, `/ban`, `/unban`, and `/lookup`. `/send` is restricted to members with Manage Server permission; choose a message and a text channel in the same server. The bot also needs permission to send messages in the chosen channel. `/sendglobalmessage` is restricted to the Discord application owner and broadcasts a message to every connected player on this game server process. The banner shows the sender's server nickname, orange name, and owner role; players who join while it is active see the remaining announcement. Set `allservers` to true. `/restart` is owner-only and lets you choose this server or all servers; currently this bot manages one game-server process, so `allservers` restarts that process. Multi-process or multi-host deployments need shared orchestration to restart other instances. `/update` is owner-only: it fetches and fast-forwards the current Git upstream, installs dependencies if a package manifest changed, builds the client assets, and restarts the server after a 20-second countdown. Push commits to the branch tracked by the server first. The server checkout must have no uncommitted changes; `/update` will stop rather than overwrite local edits. Shared pub/sub is also required to relay announcements between game-server processes. Set `DISCORD_GUILD_ID` to your server ID to register commands there immediately. Leave it blank to register globally, which can take time to appear. The server must also be in that Discord server to check member roles. A signed-in game account's owner-role status is refreshed when it joins, and `/owner` performs a fresh check. Unauthorized in-game staff commands are silently ignored. Role verification uses the bot token and `DISCORD_OWNER_ROLE_ID`, not the role name. Owner status is stored server-side for that game session; it does not change the separate clan-leader behavior. Every Discord slash-command invocation is sent to the configured activity webhook with the command name and executor; argument values are omitted. The server process must stay running for the bot to remain online. Never share or commit the bot token.

## Discord owner role

Set `DISCORD_GUILD_ID`, `DISCORD_OWNER_ROLE_ID`, `DISCORD_ADMINISTRATOR_ROLE_ID`, `DISCORD_MODERATOR_ROLE_IDS`, `DISCORD_BOT_TOKEN`, `ADMIN_API_KEY`, and `IP_BAN_SECRET` in `.env`. `ADMIN_API_KEY` and `IP_BAN_SECRET` must be long random values. Configured moderator roles or Discord Administrator permission can run moderation commands. `/ban` and `/unban` manage accounts; `/banip` and `/unbanip` manage hashed IP bans; `/lookup` returns matching account IDs, Discord IDs, usernames, and ban status. The Discord bot sends moderation requests through the loopback-only, rate-limited, signed `/api/private` admin API; moderation is disabled if `ADMIN_API_KEY` is missing. Account bans invalidate sessions and disconnect active players. IP addresses are stored only as keyed hashes. Signed-in players are checked against the owner and administrator roles when they join. Unauthorized in-game staff commands are silently ignored. Verified owners are shown in orange with `OWNER`; verified administrators are shown in red with `ADMINISTRATOR`. Both roles can open the private player roster with Tab and use `/tp <player ID>`, `/mute`, `/unmute`, `/chatcooldown <disable|enable> <player ID>`, `/builder`, and `/shield`; administrators cannot change the owner's chat cooldown or teleport to the owner's location.

Press Tab to privately open the online roster in columns of up to 10; press Tab again to close it. It excludes the staff member who opened it. Rows show each player's name, account yes/no, and Server ID; click the ID to copy it. A dash in a Server ID is a valid character in its URL-safe random format. `/tp <player ID>` teleports the staff member to a living online player. Use `/mute <player ID> <duration> [reason]` with explicit units such as `10s`, `10m`, `10h`, `10d`, `10mo`, or `10y`; omitted or blank reasons display as `no reason given`. The mute reason is shown to the muted player and included in moderation logs. Use `/unmute <player ID>` to remove a mute. `/chatcooldown disable <player ID>` and `/chatcooldown enable <player ID>` change that player's chat cooldown for their current connection only. `/shield` toggles damage immunity for the owner/administrator; attackers see “invincible!” instead of damage numbers. Its shield icon sits beside the name and moves out to make room for a clan tag and leader crown. `/clear` is available to everyone and destroys only the buildings placed by the player who ran it. Account Server IDs remain stable across sign-ins; guest IDs last for that connection. Only verified staff receive the roster and proxy/VPN range-match signal. Regular game packets do not include these private IDs. The roster's Ban/Kick/Mute buttons are visual only. Slash commands do not start or consume the chat cooldown.

Only verified Discord owners and administrators can use `/sleigh` to toggle their own sleigh while alive. It floats above the player with a matching ground shadow, ignores player/object collisions, cannot be damaged or attacked, and is ignored by hostile animals. Scroll up to increase its movement speed and down to decrease it (0.5x–20x). In sleigh mode, press `I` to zoom in and `O` to zoom out. Owners and administrators can use `/sleigh <player ID>` to toggle another online player's sleigh, including the owner.

`/builder` toggles a temporary owner/administrator building mode. It grants fast movement, immunity to damage, and passage through players and objects; hostile animals ignore builders. Press Tab for a centered, store-style catalog with Buildings and Mobs tabs; Tab or Escape closes the catalog, including after selecting a hotbar item. For owners and administrators, Tab opens the player roster; use Shift+Tab for the catalog while in Builder mode. The mouse wheel zooms the world only while the catalog is closed, and the original zoom is restored when Builder mode ends. Select a building, then place it with the mouse or touch. Select a mob, then click or hold on the world to spawn it at that location (at most once every 0.5 seconds); Builder can place any mob in any biome. Use `/clearmo` to remove only the Builder-spawned mobs you created; naturally spawning mobs and other players' Builder mobs are unaffected. Fish naturally spawn in the river, stay inside the water after entering it, and lose health over time if spawned on land; ducks spawn on grass. Vince and Sid render at Moostafa's size and use his attack animation; Vince has 20,000 health and awards 10,000 gold, 100 food, and 24,000 XP. Sid has 23,000 health, deals 65 damage per hit, and awards 15,000 gold, 150 food, and 28,000 XP. Exactly two natural Yetis are maintained at fixed snow-biome spawn points and cannot leave the snow; Builder-spawned Yetis may be placed anywhere. Yeti have 3,200 health, move at a pace just above an unprotected player's snow speed when charging, and award 4,500 gold, 800 food, and 9,000 XP. Boars spawn throughout the map, deal 16 damage on contact using a narrow, direction-aware body hitbox, do not attack players while fleeing or trapped, flee from spikes, and award 800 gold, 150 food, and 1,500 XP. Cheetahs spawn naturally in the desert but can leave it; they flee environmental hazards but retaliate when struck by players, return to their desert spawn point after a 60-second respawn delay, move more slowly than before, deal 10 damage, and have 250 health. Natural Cheetahs now spawn with clearance matching their actual collision size. Builder-spawned cheetahs may be placed anywhere. Deer and foxes spawn in normal and snow biomes, never the desert. Foxes retaliate only when attacked by a player and stop pursuing once the player leaves their view range. Builder placement ignores resource, overlap, and normal item-limit checks; builder-spawned mobs are capped at 100 active at once. Exiting builder mode restores the inventory, item counts, selected item, and movement speed from before entry; placed structures and spawned mobs remain in the world. The mode also ends when the player dies or disconnects.

Set `MAX_CONNECTIONS_PER_IP` to tune concurrent WebSocket connections per address (default `4`). Team creation is also limited to one active team per IP and three successful creations per IP per 10 minutes. Optional `PROXY_VPN_CIDRS` accepts comma-separated IP addresses or CIDR ranges; matches are a staff-visible risk signal only and never cause automatic bans. This list is local and must be maintained by the server owner; the server does not send player IPs to a lookup service. If `TRUST_PROXY=true`, WebSocket IP limits and risk checks use the last valid address in `X-Forwarded-For`, so only enable it behind a trusted reverse proxy.

To send activity logs to Discord, set `MODERATION_LOG_WEBHOOK_URL` to a private webhook for your `#logs` channel. It records all recognized in-game slash-command attempts, every Discord slash-command invocation, successful moderation actions, and automatic chat mutes or shadow mutes. Discord command entries include the executor and command name, not argument values. In-game command entries include the command text and whether the actor and target have a signed-in game account. Raw IP addresses and normal chat message contents are never sent. Leave it blank to disable webhook logging; database audit records for account/IP moderation continue to be kept as before.

The regular leaderboard keeps its original style and flips between ranks 1-10 and 11-20. Owner and administrator roles are separate from clan ownership.
